## 🌳 What is this?

**Woodstock** powers the **European Wood Construction Observatory (EWCO)** — an open, collaborative platform for collecting and sharing best practices, timber construction standards and codes, guidelines, and innovative solutions in wood construction.

At its heart sits a **retrieval‑augmented AI assistant**. Experts contribute documents; Woodstock reads them (PDFs, slides, spreadsheets, even images), breaks them into meaningful pieces, imagines the questions each piece answers, and indexes everything in a vector database. When someone asks a question, an agent searches that knowledge, reads further when it needs to, and streams back an answer **with references** so every claim can be checked.

> 💬 *"What provides wood's mechanical strength along different directions?"*
> *"Which EU funding programmes support timber construction?"*
> *"How can my project better align with New European Bauhaus values?"*

EWCO was created by experts from the **WOODSTOCK** and **TIMBERHAUS** projects at [InnoRenew CoE](https://innorenew.eu).

## ✨ Features

<table>
<tr>
<td width="50%" valign="top">

### 🔎 Agentic search
A tool‑using agent (built on [`reagent-rs`](https://crates.io/crates/reagent-rs)) queries the vector store, pulls in neighbouring chunks of a document when context is thin, and streams its answer token by token alongside the retrieved sources.

</td>
<td width="50%" valign="top">

### 🧠 HyPE indexing
Every chunk is enriched with **hypothetical questions** generated by an LLM before embedding — so user questions match content by *intent*, not just wording. Images get their own generated questions too.

</td>
</tr>
<tr>
<td valign="top">

### 📚 Reads almost anything
PDF, Word, PowerPoint, Excel, HTML, EPUB, Markdown, LaTeX, OpenDocument, e‑mail, subtitles, images and audio — converted to clean Markdown via [Docling](https://github.com/DS4SD/docling) or [Marker](https://github.com/VikParuchuri/marker).

</td>
<td valign="top">

### ⚙️ Resilient pipeline
A background worker moves each submission through staged folders — `new → loaded → chunked → hyped → embedded` — so ingestion survives restarts and failures are isolated, not fatal.

</td>
</tr>
<tr>
<td valign="top">

### 🤝 Built for contributors
Registered experts upload files, answer a short metadata questionnaire, tag content, publish posts, and leave feedback on answers — all behind JWT (Ed25519) auth.

</td>
<td valign="top">

### 🎙️ Talk to it
Voice dictation via a Whisper streaming bridge (WebSocket) or one‑shot transcription through any OpenAI‑compatible endpoint.

</td>
</tr>
<tr>
<td valign="top">

### 🔌 Bring your own model
Chat runs on **any OpenAI‑compatible API** or **Ollama**, with separate model settings for live chat and bulk ingestion. Embeddings use `bge-m3`.

</td>
<td valign="top">

### 🗂️ Zenodo harvester
A companion crate pulls open‑access records from [Zenodo](https://zenodo.org) by query, with a cursor so each run picks up where the last left off.

</td>
</tr>
</table>

---


**Ingestion.** Files land in a staging folder. The worker polls every few seconds, advancing each submission one stage at a time: conversion to Markdown (with extracted images), Markdown‑aware chunking, hypothetical‑question generation, embedding, deduplication, and finally upload to Qdrant.

**Retrieval.** The agent receives the question plus chat history, calls its RAG tool to fetch the most relevant chunks, optionally expands into the surrounding document, and streams newline‑delimited JSON events — `chunks`, `token`, `done`, `error` — back to the browser.

## 🚀 Quick start

### Prerequisites

| Tool | Why |
|---|---|
| 🦀 **Rust** (stable) | Backend server and worker |
| 🐳 **Docker** + Compose | PostgreSQL and Qdrant |
| 🦙 **Ollama** | Embeddings (`bge-m3`), optionally chat |
| 🐍 **Python 3** | Docling (auto‑installed into `.venv` on first run) |
| 📦 **pnpm** | Building the SvelteKit frontend |

### 1 · Clone and configure

```bash
git clone https://github.com/InnoRenew-CoE/woodstock.git
cd woodstock
cp .env.sample .env      # then fill it in — see Configuration below
```

### 2 · Start the databases

```bash
docker compose up -d     # PostgreSQL + Qdrant
ollama pull bge-m3       # embedding model
```

### 3 · Build the frontend

The SvelteKit app compiles straight into `public/`, which the Rust server serves as a single‑page app.

```bash
cd frontend
pnpm install
pnpm build               # → ../public
cd ..
```

For live frontend development use `pnpm dev` (serves on `:8080`).

### 4 · Provide the agent prompts

The search agent loads its instructions from `resources/agent/`, which is git‑ignored so each deployment can tune its own voice:

```
resources/agent/search_system.txt   # system prompt
resources/agent/search_prompt.txt   # prompt template
```

### 5 · Run

```bash
cargo run --release
```

On first launch Woodstock bootstraps Docling and its models (set `DUCLING_BOOTSTRAP=0` to skip), starts the ingestion worker, and serves everything on **`http://localhost:6969`** 🎉

### Try it from the terminal

`ask.sh` is a tiny streaming client with multi‑turn history:

```bash
./ask.sh "What is cross-laminated timber?"
```

## ⚙️ Configuration

All settings live in `.env`. The essentials:

<details open>
<summary><b>🌐 Server & storage</b></summary>

| Variable | Description | Default |
|---|---|---|
| `SERVER_PORT` | HTTP port | `6969` |
| `FILES_FOLDER` | Where uploaded originals are kept | — |
| `STAGING_FOLDER` | Root of the ingestion pipeline | `./staging` |
| `RAG_IMAGE_FOLDER` | Images extracted from documents | — |
| `DB_HOST` · `DB_PORT` · `DB_USER` · `DB_PASSWORD` | PostgreSQL connection | — |
| `QDRANT_SERVER` · `QDRANT_COLLECTION` | Vector store | — |
| `MAIL_SECRET` | Outgoing mail credentials | — |

</details>

<details open>
<summary><b>🤖 Models</b></summary>

| Variable | Description | Default |
|---|---|---|
| `CHAT_PROVIDER` | `openai-compatible` or `ollama` | — |
| `CHAT_MODEL` | Model used by the search agent | `DeepSeek-V4-Flash` |
| `OPENAI_COMPATIBLE_BASE_URL` | Any `/v1/chat/completions` endpoint | `http://localhost:11434/v1` |
| `OPENAI_COMPATIBLE_API_KEY` | Key for that endpoint | — |
| `OLLAMA_HOST` · `OLLAMA_PORT` | Ollama for embeddings / chat | — |
| `INGESTION_CHAT_PROVIDER` · `INGESTION_OLLAMA_HOST` · `INGESTION_OLLAMA_PORT` · `INGESTION_MODEL` | Separate model config for the ingestion worker | — |

</details>

<details>
<summary><b>📄 Document conversion</b></summary>

| Variable | Description | Default |
|---|---|---|
| `DUCLING_BOOTSTRAP` | Install/check Docling on startup | `1` |
| `DUCLING_VENV` | Python virtualenv for Docling | `.venv` |
| `DUCLING_BIN` | Docling wrapper script | `.local-bin/docling` |
| `DUCLING_ARTIFACTS_PATH` | Downloaded Docling models | `.docling-models` |
| `DUCLING_NUM_THREADS` | Conversion threads | `2` |
| `DUCLING_DEVICE` | `cpu`, `cuda`, … | `cpu` |
| `DUCLING_OCR` | Enable OCR for scanned files | `0` |
| `MARKER_BASE_URL` · `ADMIN_TOKEN` | Optional GPU [Marker](marker/) server | — |

## 📡 API

| Method | Route | Auth | Purpose |
|---|---|:-:|---|
| `GET` / `POST` | `/chat/search` | | Ask a question; streams NDJSON (`POST` carries chat history) |
| `GET` | `/chat/download/{file_id}` | | Download a cited source document |
| `GET` | `/rag/images/{document_id}/{image}` | | Images extracted from documents |
| `POST` | `/login` · `/register` | | Contributor authentication |
| `GET` | `/posts` | | Public posts |
| `GET` | `/audio` | | WebSocket bridge to a Whisper server |
| `POST` | `/transcribe` | | One‑shot audio transcription |
| `GET` | `/questions` · `/tags` · `/files` | 🔒 | Contribution form data, tags, your files |
| `POST` | `/answers` · `/submit` | 🔒 | Upload a document with its metadata |
| `POST` | `/feedback` · `/collaborate` · `/verify` · `/invalidate` | 🔒 | Feedback, posts, session management |

## 🗺️ Project layout

```
woodstock/
├── src/
│   ├── main.rs            # boot: Docling → worker → server
│   ├── server/            # Actix routes, auth, streaming, audio
│   ├── worker/            # staged ingestion loop
│   ├── rag/
│   │   ├── agent.rs       # tool-using search agent
│   │   ├── loading/       # Docling, Markdown, text loaders
│   │   ├── processing/    # chunking, HyPE, image HyPE, dedup, embedding
│   │   └── comm/          # Qdrant, Ollama/OpenAI, Marker, Docling clients
│   └── db/                # PostgreSQL
├── frontend/              # SvelteKit 5 + Tailwind 4 → builds into public/
├── zenodo/                # Zenodo open-access harvester
├── marker/                # optional FastAPI + Marker GPU conversion server
├── docker-compose.yml     # PostgreSQL + Qdrant
└── ask.sh                 # terminal chat client
```
